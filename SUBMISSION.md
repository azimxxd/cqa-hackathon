# Saw-cell: подготовка к проверке жюри

Официальный формат — JSON 1.0 из приложения к студенческому гайду Freedom Broker.
Команда: **Saw-cell**. В DEV должны быть 60 чатов и 5 звонков; в PROD — 10 контрольных чатов.

## Получение данных

В локальном `.env` задайте `ORG_API_URL` ссылкой GET из гайда организаторов.
Ссылка может содержать подпись доступа: не коммитьте `.env` и не вставляйте её в отчёты.
Импортируйте DEV через интерфейс. Для контрольного набора используйте точное значение
`group_id`, полученное от организаторов; не подбирайте его.

Исходные данные и база остаются в `data/`, отдельно от файлов сдачи.
`shared/mocks/`, режим FAKE и тестовые провайдеры предназначены для проверок кода.
Их результаты не являются настоящей сдачей.

## Оценка через Algos

В этом рабочем процессе задания и оценка диалогов запускаются из чата с управляющим
агентом через Algos. Доступные модели и остатки лимитов проверяются до запуска.
Аккаунты разработки и оценки могут работать независимо; исчерпанные лимиты не
сбрасываются и не обходятся. Это отдельный путь от встроенных Gemini/Ollama.
Кнопка обычной оценки использует провайдер из `.env` и требует его настройки.

Результаты Algos сохраняются порциями и проходят строгую проверку до загрузки в БД:

```sh
node scripts/import-algos-assessment.js \
  --input data/algos-assessments/reviewed \
  --dataset data/dev.json \
  --model "gpt-6-luna + gpt-6.1-sol" \
  --run 004db0d23ad4 \
  --version 1
```

Указан идентификатор реального DEV-запуска с первичной оценкой и вторым модельным
проходом. Для нового набора используйте его собственный запуск, а не произвольный
идентификатор как доказательство выполненной оценки. Сами выводы должны быть получены
моделью по исходным диалогам. Импорт не генерирует ответы и не исправляет оценки
по ключевым словам. Повтор одинаковой загрузки не создаёт новые оценки.

Имя модели хранится вместе с оценкой. Неизмеренные токены, время отдельных диалогов
и стоимость вызовов не подменяются выдуманными записями `llm_calls`.
Подписочные оценки Algos не следует считать измеренным бесплатным API-прогоном.

## Экспорт

Экран «Сдача жюри» показывает набор, версию чек-листа, исходные или финальные оценки,
полноту, ошибки и официальный JSON. Официальный профиль содержит ровно восемь
критериев. Пользовательский чек-лист сохраняется отдельно; его изменения не должны
незаметно выдавать несовместимые оценки за официальный формат.

```sh
npm run submission:export -- --dataset=DEV --group_id=DEV --checklist_version_id=1 --source=final
npm run submission:validate -- results/dev/results.json --dataset=DEV --source=data/dev.json
```

DEV сохраняется в `results/dev/results.json`, PROD — в `results/prod/results.json`.
Для PROD экспорт выполняется после получения и обработки контрольного набора.
Нельзя создавать фиктивные контрольные ID или копировать DEV под видом PROD.

В `status: "ok"` должны присутствовать все восемь критериев:
`contact`, `discovery`, `identification`, `consultation`, `empathy`, `dialogue`,
`closure`, `critical`. Доказательства нумеруются с 1 по полному исходному
транскрипту, включая клиента, бота и события. N/A исключается из знаменателя
при пересчёте весов. Грубая ошибка передаётся отдельным флагом и не обнуляет итог.

Если диалог оценить не удалось, его ID остаётся в результатах с `status: "error"`,
`criteria: []`, `score: null` и непустой причиной. Ошибка не является оценкой 0.

## Проверка качества и ограничения

Тесты программы, корректная структура JSON и согласие с имеющейся разметкой — разные
проверки. Сравнение с файлами `eval/labels/` полезно для поиска расхождений, но
независимость и качество этой разметки требуют отдельной проверки человеком.
Для звонков оценка транскрипта не доказывает качество дикции или интонации.

Перед демонстрацией проверьте полный сценарий: диалог → доказательство → апелляция →
решение с причиной → новый итог; затем добавление/изменение критерия и новую версию.
Сдачу в публичный Git выполняйте отдельно после проверки результатов и получения
разрешения владельца репозитория. Локальная подготовка файлов сама по себе не
означает, что организаторы их получили.
