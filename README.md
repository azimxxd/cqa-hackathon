# CQA — Conversation Quality Analytics

Прототип для хакатона Freedom Broker: импорт чатов и звонков → оценка операторов
по версионируемому чек-листу → доказательства → апелляция → решение проверяющего
→ пересчёт. Интерфейс работает с сохранёнными данными и реальными API сервера.

Объединённое рабочее пространство использует компоновку версии тиммейта: лента
диалогов слева, переписка и запись в центре, критерии и редактор справа. Оформление
сохранено из нашей версии: локальный Manrope, тёмная навигация, светлые панели и
лаймовый акцент. Подробности объединения — [TEAMMATE_MERGE.md](docs/TEAMMATE_MERGE.md).

Подготовка файлов жюри для команды **Saw-cell**, работа с настоящими оценками Algos
и ограничения проверки качества описаны в [SUBMISSION.md](SUBMISSION.md).

План команды — [PLAN.md](PLAN.md), контракт — [shared/schemas.md](shared/schemas.md),
подробности сервера — [server/README.md](server/README.md),
экраны и возможности интерфейса — [web/README.md](web/README.md).

## Запуск

Нужен Node.js ≥ 22.13 (встроенный `node:sqlite`).

```sh
npm install
cp .env.example .env
# Заполнить ORG_API_URL и GEMINI_API_KEY в локальном .env
npm start
```

Откройте http://localhost:3000. SQLite по умолчанию — `data/cqa.db`;
`CQA_DB_PATH` задаёт другой файл. Ключи и данные организаторов остаются локально.

## Настройки

| Переменная | Значение / назначение |
|---|---|
| `PORT` | `3000` |
| `CQA_DB_PATH` | `data/cqa.db` |
| `ORG_API_URL` | URL API организаторов, GET с `group_id` |
| `LLM_PROVIDER` | `gemini` (по умолчанию) или `ollama` |
| `GEMINI_API_KEY` | Ключ Gemini, передаётся только заголовком |
| `GEMINI_API_KEYS` | Необязательный пул ключей через запятую, точку с запятой или пробел; имеет приоритет над GEMINI_API_KEY |
| `GEMINI_MODEL` | `gemini-3.1-flash-lite` |
| `GEMINI_TRANSCRIBE_MODEL` | `gemini-3.1-flash-lite`, отдельная модель распознавания аудио |
| `GEMINI_MAX_ATTEMPTS` | `4`, включая первую HTTP-попытку |
| `GEMINI_MAX_BACKOFF_MS` | `30000`, максимум задержки, включая `retry-after` |
| `GEMINI_THINKING_BUDGET` | Необязательный бюджет thinking для Gemini 2.5 |
| `OLLAMA_URL` / `OLLAMA_MODEL` | `http://localhost:11434` / `qwen2.5:14b` |
| `OLLAMA_MAX_BACKOFF_MS` | `3000`, максимум задержки, 3 HTTP-попытки |
| `LLM_CONCURRENCY` | `6`, число одновременно оцениваемых диалогов |
| `LLM_RETRIES` / `LLM_BACKOFF_MS` | `1` / `1000`: повторы сервера только после исчерпания временных ошибок провайдера |
| `AI_CACHE_DIR` | Необязательный кеш самостоятельного ИИ/eval; сервер его обходит |
| `PRICE_INPUT_PER_M` / `PRICE_OUTPUT_PER_M` | `0.25` / `1.5`, коэффициенты расчётной стоимости за миллион токенов; задайте по своему тарифу |
| `CQA_FAKE_LLM` | `1` включает явные детерминированные результаты `FAKE`, без модели и затрат |

Заданная модель не заменяется автоматически при 404: запрос завершится явной
ошибкой. Для смены модели измените GEMINI_MODEL. Пул ключей ротируется в пределах
GEMINI_MAX_ATTEMPTS; смены модели при ротации нет. Ключи одного проекта могут
делить общий лимит. Подтверждённое исчерпание дневной квоты останавливает повторы.

## Звонки и Gemini

Положите локальные MP3 в `data/audio/<conversation_id>.mp3` или используйте
`audio_url` из импорта. Плеер обращается к серверу и поддерживает перемотку.
В карточке звонка нажмите «Расшифровать Gemini», затем переключите текст на
«Gemini». Это отдельный запрос с аудио в Gemini API; модель получает ID и временные
метки реплик. Старый обычный текст не передаётся как подсказка. Служебные строки и
строки с масками сохраняются, а исходная расшифровка остаётся доступной.

«Переоценить по Gemini» использует выбранную готовую расшифровку. Оценка сохраняет
имя модели, источник и хеш текста. Пакетная оценка использует исходный текст.
Кеш распознавания учитывает аудио, исходные реплики, модель и версию промпта.
Ключи, записи и кеши не входят в Git. Ошибки API показываются явно; эвристическая
оценка не подставляется вместо ответа модели.

Версия промпта берётся из `ai/prompt.js` (экспортируется через `ai/evaluate.js`).
Переменная окружения `PROMPT_VERSION` больше не используется. Порог первой реакции
входит в кеш c06 автоматически. Старые хеши критериев в локальных БД становятся
промахами кеша после перехода на структурированный хеш; сами оценки сохраняются.
Повреждённый JSON кеша также считается промахом: переоценивается только затронутый
критерий. Файлы ИИ-кеша заменяются атомарно, через временный файл.

## Проверки и метрика

```sh
npm test
node server/verify-start.js
node scripts/e2e-stub.js
node eval/edge_cases.js  # проверка пограничных случаев с заглушками
npx -y node@22.13.0 --test
```

Тесты подменяют модель и API организаторов; E2E использует временную БД.
`verify-start` запускает `npm start` на отдельной временной БД и проверяет health.

```sh
npm run eval -- --limit 20
npm run eval -- --only p1-ru-001 --no-cache
```

`--concurrency` (или `LLM_CONCURRENCY`) и `--limit` должны быть положительными
целыми числами. Неверные значения отклоняются до загрузки набора данных;
параметр `--concurrency` имеет приоритет над переменной окружения.

Eval — отдельный запуск с выбранным провайдером; при `gemini` он вызывает модель
и может расходовать лимит/деньги. `data/dev.json` используется локально, при его
отсутствии данные запрашиваются у организаторов. Отчёты — `eval/reports/`.
Ошибочные оценки входят в точность как промахи; отчёт отдельно показывает число
ошибок и ответов из кеша. Средняя стоимость полной оценки включает неудачные
попытки и исключает частичные пересчёты/полностью кешированные оценки.

## Команда и git

Общая версия включает сервер, интерфейс и AI с исправлениями ревью.
Состав объединения и результаты проверок — [UNIFIED_REPORT.md](UNIFIED_REPORT.md).

| Кто | Зона | Папки |
|---|---|---|
| Азамат | Сервер, БД, расчёт итога, контракты | `server/`, `shared/` |
| Нурлат | Интерфейс | `web/` |
| Алдияр | Оценка моделью и метрика | `ai/`, `eval/` |

Изменения ИИ и eval сохраняйте отдельно, с префиксами `ai:` и `eval:`;
сервер — `server:`, контракты — `shared:`, общие файлы — `repo:`.
Перед коммитом проверяйте `git status --ignored`: `git add -A` не должен захватывать
ключи, локальные данные организаторов, БД, кеши или отчёты. `.gitignore` исключает
`.env`, `data/*.json`, `data/ai-cache/`, `eval/reports/`, `eval/.cache/`, `eval/data/`
и SQLite. Исходные `shared/mocks/` — только тестовые фикстуры.
