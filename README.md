# CQA — Conversation Quality Analytics · команда Saw-cell

Прототип для хакатона Freedom Broker: система автоматически оценивает работу
операторов в чатах и звонках по настраиваемому чек-листу, показывает обоснование
со ссылкой на конкретную реплику, принимает апелляции и пересчитывает итог после
решения проверяющего.

- **8 критериев официального чек-листа**, веса, шкалы и N/A с перераспределением веса.
- **RU / KZ / EN**, чаты и звонки (плеер с переходом к фрагменту записи).
- **Доказательства**: клик по реплике в обосновании прокручивает переписку или перематывает запись.
- **Апелляция → решение проверяющего → новый итог**, исходная оценка сохраняется.
- **Редактор чек-листа**: замена критерия, новая версия, переоценка только изменённых критериев.
- **Локальная модель на собственном GPU** или облачный Gemini — переключение одной переменной.
- **Экспорт для жюри** в формате JSON 1.0 со строгой проверкой.

## Быстрый старт

Нужен Node.js ≥ 22.13 (используется встроенный `node:sqlite`, внешней БД нет).

```sh
npm install
cp .env.example .env      # вписать ORG_API_URL и ключ модели (см. ниже)
npm start                 # http://localhost:3000
```

Без ключей интерфейс можно посмотреть в демо-режиме: `CQA_FAKE_LLM=1 npm start`
(оценки помечены как FAKE и не идут в сдачу).

### Выбор модели

| Режим | `.env` | Стоимость оценки |
|---|---|---|
| Локально, Qwen на своём GPU | `LLM_PROVIDER=ollama`, `OLLAMA_URL=http://localhost:11434`, `OLLAMA_MODEL=qwen3.6:35b-a3b` | $0 за вызов (оплачивается только аренда GPU) |
| Облако, Gemini | `LLM_PROVIDER=gemini`, `GEMINI_API_KEY=…`, `GEMINI_MODEL=gemini-3.1-flash-lite` | считается по токенам каждого вызова и видна в UI (`#stats`) |

Настройка GPU-сервера (NVIDIA L40S, Ollama, faster-whisper) — [docs/GPU_SERVER.md](docs/GPU_SERVER.md).

## Сценарий демо (5 минут)

1. **Диалоги** (`#dialogs`) — импорт набора по `group_id`, лента с фильтрами по языку, каналу и итогу.
2. **Карточка диалога** — оценка по 8 критериям: ответ, баллы, вес, обоснование.
   Клик по `m010` ведёт к реплике; у звонка — к моменту записи. Пример N/A и итог 0–100.
3. **Апелляция** — оспорить критерий с комментарием; в `#appeals` проверяющий видит
   спорную оценку и фрагмент, подтверждает или меняет её — итог пересчитывается.
4. **Чек-лист** (`#checklist`) — заменить критерий, сохранить новую версию и применить
   её к выданным диалогам: модель переоценивает только изменённый критерий.
5. **Сдача жюри** (`#submission`) — полнота, ошибки и готовый `results.json`.

## Как устроена оценка

```
API организаторов ─► server (Express + SQLite) ─► очередь оценок ─► ai/evaluate.js ─► Qwen / Gemini
                         │                                              │
                         └─► web (HTML/CSS/JS, готов к Dynamics 365)    └─► проверка ответа кодом
```

- **Промпт** строится из активной версии чек-листа — критерии нигде не захардкожены.
  Метки времени, паузы, первая реакция и уточняющие вопросы считаются кодом и
  передаются модели как факты (`ai/timing.js`).
- **Строгая проверка**: id реплик существуют, значение из шкалы, N/A только где разрешён,
  для «Нет» указан проверенный участок. Невалидный ответ — одна повторная попытка
  с обратной связью, затем явная ошибка. Выдуманных оценок нет.
- **Проверка цитат**: если в обосновании есть цитата, которой нет в диалоге, оценка получает
  бейдж «Требует проверки» — ответ модели не подменяется.
- **Защита от prompt injection**: текст диалога передаётся как недоверенные данные.
- **Самосогласованность** (`LLM_SAMPLES=3`): несколько прогонов и голосование.
- **Расчёт итога** строго по чек-листу: шкала → баллы по весу, N/A исключается с
  перераспределением, округление до 2 знаков, грубая ошибка — отдельный флаг.

## Точность

Сверка с ручной разметкой всех 65 DEV-диалогов (`npm run eval`), промпт v16:

| Модель | Точность по критериям | MAE итога | Грубые ошибки | Время на 65 диалогов |
|---|---|---|---|---|
| Qwen3.6-35B-A3B (Q4, локально, L40S) | **0.960** | 2.61 | 1.00 | ≈ 6.7 мин |

Разметка сделана командой, и промпт улучшался на этих же диалогах, поэтому на новых
данных точность ожидаемо ниже. Отчёты — `eval/reports/`.

## Сдача результатов

```sh
npm run prod -- --group_id=<id от организаторов>
```

Одна команда: импорт → проверка состава (PROD — 10 чатов) → оценка неоценённых →
экспорт `results/prod/results.json` → валидация по исходному набору. Подробно —
[SUBMISSION.md](SUBMISSION.md). Файлы: `results/dev/results.json`, `results/prod/results.json`.

## Структура

| Папка | Что внутри |
|---|---|
| `server/` | Express API, SQLite, очередь оценок, расчёт итога, апелляции, импорт |
| `ai/` | Промпт, правила по критериям, провайдеры Gemini/Ollama, проверка ответов, расшифровка звонков |
| `web/` | Интерфейс на чистых HTML/CSS/JS, обёртка для Dynamics 365 (`web/d365.js`) |
| `eval/` | Ручная разметка 65 диалогов, метрики, отчёты |
| `shared/` | Чек-лист по умолчанию, контракты данных, формат сдачи |
| `scripts/` | Контрольный прогон, экспорт и валидация результатов, GPU-бенчмарк |

| `GEMINI_MAX_BACKOFF_MS` | `30000`, максимум задержки, включая `retry-after` |
| `GEMINI_THINKING_BUDGET` | Необязательный бюджет thinking для Gemini 2.5 |
| `OLLAMA_URL` / `OLLAMA_MODEL` | `http://localhost:11434` / `qwen2.5:14b` |
| `OLLAMA_THINK` | `1` включает режим размышления гибридных моделей (Qwen3.x); по умолчанию выключен |
| `OLLAMA_NUM_CTX` | `16384`, окно контекста локальной модели |
| `OLLAMA_MAX_BACKOFF_MS` | `3000`, максимум задержки, 3 HTTP-попытки |
| `LLM_SAMPLES` | `1`; 2–5 включает самосогласованность: доп. прогоны с `LLM_SAMPLE_TEMPERATURE` (`0.7`), голосование по yes/no/N/A и нижняя медиана по шкале |
| `LLM_CONCURRENCY` | `6`, число одновременно оцениваемых диалогов |
| `LLM_RETRIES` / `LLM_BACKOFF_MS` | `1` / `1000`: повторы сервера после исчерпания временных ошибок провайдера |
| `AI_CACHE_DIR` | Необязательный кеш для eval; сервер его обходит |
| `PRICE_INPUT_PER_M` / `PRICE_OUTPUT_PER_M` | `0.25` / `1.5`, цена за миллион токенов для расчёта стоимости |
| `CQA_FAKE_LLM` | `1` — детерминированные результаты `FAKE`, без модели и затрат |

Модель не подменяется автоматически при ошибке: запрос завершится явной ошибкой.
Конфигурация оценки (число ответов, температура, thinking, окно контекста) сохраняется
с заданием и входит в кеш; после её изменения старые результаты не переиспользуются.

<summary><b>Звонки и расшифровка Gemini</b></summary>

Положите MP3 в `data/audio/<conversation_id>.mp3` или используйте `audio_url` из импорта.
Плеер поддерживает перемотку к реплике. «Расшифровать Gemini» отправляет аудио в
Gemini API с ID и метками реплик; исходная расшифровка остаётся доступной.
«Переоценить по Gemini» использует готовую расшифровку и сохраняет модель, источник
и хеш текста. Подробнее — [docs/GEMINI_AUDIO_API.md](docs/GEMINI_AUDIO_API.md).
