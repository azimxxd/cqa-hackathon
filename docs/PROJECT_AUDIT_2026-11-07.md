## Исходные находки

1. **Кеш сервера не учитывает режим голосования.** `server/jobs.js`, `cacheKey` и
   `promptKey` не включают `LLM_SAMPLES` и параметры дополнительных выборок.
   В изолированной SQLite первая оценка при samples=1 вызвала провайдер; после
   перезапуска сервиса при samples=3 повторная оценка завершилась без нового вызова.
   Нужно включить конфигурацию оценивания в ключ кеша, метаданные и восстановление
   очереди. Самостоятельный AI-кеш учитывает число выборок, но не их температуру.

2. **Проверка цитат не проверяет правильность доказательства и автора.**
   `quoteFlags` принимает совпадение в любом сообщении диалога. Воспроизведено:
   explanation приписывает оператору обещание доходности, evidence_ids указывает
   на приветствие оператора, сама фраза есть только у клиента — флагов нет.
   Нужны отдельные проверки ссылки на доказательство и приписываемого автора,
   с сохранением поддержки переводов и корректных цитат клиента как контекста.

3. **Нет полного замера текущей конфигурации.** Код содержит промпт v16.
   Последний отчёт `eval/reports/latest.json` относится к Qwen с v15: согласие с
   имеющимися DEV-метками 94%, MAE 3.12 по 64 успешным оценкам, одна ошибка
   `p1-kz-005` (несуществующий checked_range у c07). Эти цифры не доказывают
   качество v16, голосования или текущей Gemini-конфигурации приложения.
   Нужно устранить причину ошибки, зафиксировать конфигурацию и сравнить полный
   прогон на одинаковом наборе. DEV-метки не являются независимым тестом PROD.

4. **Файлы сдачи относятся к предыдущему прогону.** DEV JSON содержит модель
   `gpt-6-luna + gpt-6.1-sol`, а не свежий Qwen/Gemini. После выбора финальной
   конфигурации нужен согласованный экспорт и сведения о его происхождении.
   PROD results.json отсутствует; нужен настоящий контрольный набор организаторов.
   Новая команда prod по умолчанию пропускает готовые оценки по статусу, не сверяя
   модель/промпт: при смене конфигурации это необходимо учитывать.

5. **Качество ASR не измерено независимо.** Полнота ID и сохранение меток времени
   не гарантируют правильную привязку каждой фразы к роли и позиции. Проверить
   спорные места пяти звонков по записи перед использованием для сдачи.

## Сохранение и документация

Новые изменения в AI, UI, GPU-инструментах и команде PROD пока не закоммичены.
После устранения ошибок стоит сохранить согласованную версию в отдельной ветке.
`ADDITIONS_PLAN.md` частично устарел: например, eval уже использует общий серверный
scoring, а подготовка GPU описана в отдельном отчёте как выполненная.

Приоритет: кеш голосования → достоверность цитат → полный замер выбранной
конфигурации → проверка аудио и согласованные результаты сдачи.
