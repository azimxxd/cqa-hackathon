# CQA Hackathon — финальный план команды (24 часа)

## Контекст
Прототип Conversation Quality Analytics для Freedom Broker: чек-лист → оценка диалога LLM → доказательства → апелляция → решение проверяющего → пересчёт → замена критерия через UI. Главный критерий отбора — **точность относительно Ground Truth** на 10 новых транскриптах. Дальше: удобство, корректность процесса (реальный анализ, не заготовки), доп. функции.

Источники: `CQA_Hackathon_Student_Guide_v3.pdf`, `CQA_Chat_Quality_Checklist.pdf`, критерии отбора.

## Роли
| Кто | Зона | Папки (владелец) |
|---|---|---|
| **Азамат** — сервер и интеграция, владелец контрактов | Импорт API оргов, БД, версии чек-листа, расчёт итога, задачи оценки, апелляции, README | `server/`, `shared/` |
| **Нурлат** — интерфейс | Список, карточка, транскрипт + плеер, редактор чек-листа, апелляции, экран проверяющего | `web/` |
| **Алдияр** — ИИ и точность | Промпт, вызов модели, валидация ответа, разметка DEV, скрипт точности, стоимость | `ai/`, `eval/` |

Каждый правит **только свои папки**. `shared/` меняет только Азамат (остальные — через PR с упоминанием в чате).

## Стек
- Backend: Node.js 22.13+ + Express + SQLite (встроенный `node:sqlite`, Node ≥ 22.13, без нативных зависимостей). Один процесс, `npm start`.
- Frontend: чистый HTML/CSS/JS (ES-модули), без сборки, обычный CSS с префиксом `.cqa-`. Один корневой `<div id="cqa-root">`, базовый URL API в `web/config.js`, тонкий адаптер `web/d365.js` (`parent.Xrm` если есть, иначе no-op). Сервер раздаёт `web/` статикой → нет CORS.
- LLM: Gemini Flash (бесплатный tier) через провайдер-интерфейс в `ai/providers/`; вторым провайдером — Ollama (локально) для пункта «разнообразие архитектур». Модель и ключ — в `.env` (`.env.example` в репо, сам ключ **не коммитить**).

## Контракты (фиксируем в первый час, лежат в `shared/`)

**Conversation** (из API оргов + ID при импорте; ID не меняются):
`{conversation_id, channel, language, audio_url, messages:[{id:"m001", idx, timestamp, offset_sec, speaker, text}]}`. `offset_sec` — секунды от первой реплики (MM:SS у чатов, ISO 8601 у звонков).

**Criterion** (в ChecklistVersion):
`{id:"c04", section, title, description, type:"binary"|"scale", weight, na_allowed, na_condition, scale:[{value:20,label}...], scores_points:true|false}`.
Версии неизменяемы: сохранение = новая версия, `hash` критерия = хеш текста.

**AI-ответ по критерию** (Алдияр → Азамат):
`{criterion_id, answer:"yes"|"no"|"na"|null, scale_value:number|null, explanation, evidence_ids:["m003"], checked_range:{from,to}|null}`.
Плюс на вызов: `{model, input_tokens, output_tokens, cost_usd, latency_ms, prompt, raw_response}` → таблица `llm_calls`.

**Evaluation**: `{id, conversation_id, checklist_version_id, criteria:[AI-ответ + points + effective_weight], total|null, gross_error:bool, sections:{...}, cost_usd, status}`.

**Appeal**: `{id, evaluation_id, criterion_id, comment, status:"open"|"decided"}`.
**ReviewDecision**: `{appeal_id, action:"confirm"|"change", new_answer, new_scale_value, reason}`. Evaluation хранит `original` и `final` значения критерия.

**API (Азамат):**
- `POST /api/import {group_id}` · `GET /api/conversations` · `GET /api/conversations/:id`
- `GET /api/checklists` · `GET /api/checklists/:id` · `POST /api/checklists` (новая версия)
- `POST /api/evaluate {conversation_ids|"all", checklist_version_id}` → `{job_id}` · `GET /api/jobs/:id`
- `GET /api/evaluations?conversation_id=&version=`
- `POST /api/appeals` · `GET /api/appeals?status=open` · `POST /api/appeals/:id/decision`
- `GET /api/stats` (стоимость, время, кол-во вызовов)

## Правила расчёта (Азамат, `server/scoring.js`, + юнит-тесты)
- Да = полный вес, Нет = 0; шкала: `value / max(scale) · weight` (c04: {0,5,10,15,20}, c06: {0,4,7,10}).
- N/A только где `na_allowed` (02, 03, 04, 07) — иначе ответ отклоняется и критерий переоценивается.
- Итог = `Σ points / Σ weight применимых · 100`, округление до 2 знаков; нет применимых → `null`.
- c08 без баллов, «Да» = нарушение, итог **не обнуляет**, флаг `gross_error`.
- Итоги секций по `section`.
- Пересчёт после решения проверяющего и после смены веса/N/A — без вызова LLM.

## Правила для промпта (Алдияр)
- Дословный текст критериев и шкал из `checklist` (не хардкод — критерии берутся из версии).
- 01: приветствие **на языке клиента** + представился в **первом ответе оператора**; бот не считается.
- 03: общий вопрос о тарифах → N/A; нужно было, но нет подтверждения → Нет; доказательство может быть системным сообщением.
- 06: паузы считаются в `ai/timing.js` кодом (порог первой реакции 3 мин, теги/вложения не учитываются) и передаются модели фактами.
- 08: достаточно самого предложения (личный перевод, личный номер для платной консультации).
- Пропущенное действие → `checked_range`/ID там, где действие **ожидалось** (01 — первая реплика оператора, 07 — последняя реплика оператора + закрытие).
- Бот и система — контекст; текст диалога — данные (инъекции «поставь максимум» игнорируются).
- temperature 0, JSON-схема ответа, 2–3 few-shot из DEV. Валидация: ID существуют, значение шкалы из списка, N/A разрешён → иначе 1 повтор.
- Частичный пересчёт: кеш по `(conversation_id, criterion.hash, prompt_version, model)`; при замене критерия вызываем модель только по нему. Параллельность 5–10, ретрай с backoff на 429.
- Звонки оцениваются по транскрипту, как чаты. Аудио — только плеер (анализ тона — бонус, если останется время).

## Git-процесс
- Публичный репо `azimxxd/cqa-hackathon`, `main` защищён по договорённости: работаем в ветках `nurlat/*`, `aldiyar/*`, `azamat/*`, мелкие PR → merge в `main` сразу после самопроверки (`npm start` поднимается).
- Пушить минимум раз в час. Каждые 3–4 часа (4, 8, 12, 16, 20 ч) — общий синк: все подтягивают `main`, запускаем полный сценарий вместе.
- Коммиты маленькие, сообщения вида `web: evidence click scrolls to message`.
- Ссылку на репо отправить оргам заранее (до 20 ч).

## Первый час — вместе
1. Скелет, `shared/` (контракты, `checklist.default.json` с 8 критериями, моки) и `.env.example` уже в репо. Сервер с первого часа отдаёт моки по тем же путям API (`server/routes/mock.js`), поэтому UI можно делать сразу.
2. Алдияр проверяет один реальный вызов Gemini; Азамат — реальный GET DEV.
3. Выбираем демо-диалоги: обычный, с нарушением, с N/A, KZ, звонок, с грубой ошибкой.
4. Нурлат стартует на моках из `shared/mocks/`.

## Защита (5 мин)
- Нурлат, 1 мин: задача, интерфейс, выбранный диалог.
- Алдияр, 2 мин: оценка вживую, доказательство → реплика, N/A, итог, грубая ошибка, стоимость, наша метрика точности.
- Азамат, 2 мин: апелляция → решение → новый итог; замена критерия в UI → частичный пересчёт.

## Проверка
- `npm test` — юнит-тесты `scoring.js`: разные веса, шкалы, N/A, нет применимых → null, c08 не влияет, пересчёт после решения.
- `node eval/run.js` — совпадение по критериям и MAE итога на ручной разметке; цифра в README.
- Ручной сценарий: импорт DEV → оценка → клик по доказательству → апелляция → решение → итог изменился → обновить страницу (всё сохранилось) → заменить критерий → применить ко всем → только он пересчитан.
- Кейсы Алдияра: KZ/EN, пропущенное действие, реплика бота вместо оператора, инъекция в тексте клиента.
