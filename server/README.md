# Server core

Node.js 22.13+; Express и встроенный `node:sqlite`. Из корня репозитория:

```sh
npm test
npm start
```

SQLite создаётся в `data/cqa.db` относительно репозитория. Первая версия
чек-листа загружается из `shared/checklist.default.json`; последующие версии
создаются только через `POST /api/checklists`. `CQA_DB_PATH` позволяет выбрать
другой файл, например для изолированной проверки.

## Импорт

Задайте `ORG_API_URL` в локальном `.env`. `POST /api/import {"group_id":"DEV"}`
делает GET на этот URL с query-параметром `group_id`, сохраняя остальные параметры.
Ответ организаторов должен содержать `isSuccess: true`; массив Conversation
читается из `data`, `data.conversations` или `conversations`.
Сами Conversation соответствуют `shared/schemas.md`. Реальный ответ организаторов
в репозитории пока отсутствует: при другой оболочке потребуется адаптация импорта.

Порядок сообщений сохраняется, ID назначаются `m001`, `m002`, …; `timestamp`
остаётся исходным, `offset_sec` считается от первой реплики. Пакет сохраняется
транзакцией. Повторный импорт тех же данных безопасен. Изменённое содержимое
под прежним conversation_id отклоняется, чтобы не испортить доказательства
и кеш ранее созданных оценок.

## Очередь и модель

`POST /api/evaluate` принимает `conversation_ids` (массив или `"all"`) и числовой
`checklist_version_id`. Возвращает `{job_id}` с HTTP 202. `GET /api/jobs/:id`
возвращает `{status, done, total, errors}`. `done` — число завершённых попыток
оценки диалогов, включая ошибки; `errors` содержит `{conversation_id, error}`.
Состояния: `queued`, `running`, `done`, `error`.

Настройки в окружении / локальном `.env`:

- `LLM_CONCURRENCY=6`: максимум одновременно обрабатываемых диалогов для всех задач.
- `LLM_RETRIES=3`: число повторов временных ошибок 429/5xx и сетевых ошибок.
- `LLM_BACKOFF_MS=1000`: начальная задержка; затем увеличивается вдвое.
- `PROMPT_VERSION=v1`: версия промпта для кеша. Менять при изменении промпта
  или правил, влияющих на оценку, включая порог первой реакции.
- `LLM_PROVIDER`, `GEMINI_MODEL`, `OLLAMA_MODEL`: модель в ключе кеша;
  провайдер вызывается через `ai/evaluate.js` по согласованному интерфейсу.
- `CQA_FAKE_LLM=1`: явный тестовый режим до готовности ИИ. Детерминированные
  результаты помечены `FAKE`, модель называется `fake`, стоимость нулевая.
  Этот режим не проверяет качество ИИ. По умолчанию вызывается настоящий модуль;
  пока он заглушка, задача честно завершается с ошибкой.

Кеш хранится в `criterion_results`: `(conversation_id, criterion.hash,
prompt_version, model)`. Переиспользуются исходные ответы успешных оценок.
Модель получает только критерии без кеша; неверный ответ повторяется один раз.
Изменения веса / разрешения N/A сами по себе не меняют хеш и не вызывают LLM.
Если N/A запретили для уже сохранённого ответа N/A, новая оценка завершается
ошибкой без LLM: сервер не подменяет его произвольным yes/no. Для новой оценки
такого критерия нужно изменить текст его условий либо версию промпта.
Решения проверяющего привязаны к конкретной Evaluation, в кеш исходных ответов
они не попадают.

Задачи и оценки сохраняются в SQLite. После перезапуска незавершённые задачи
продолжаются; запускать следует с прежними настройками модели и промпта.
При прерывании процесса во время внешнего запроса возможен повтор вызова модели.
SIGTERM/SIGINT дожидаются активных обработчиков; очередь остаётся для следующего
запуска. Это один серверный процесс, без внешнего брокера задач.

## Апелляции и статистика

Маршруты и формы данных соответствуют `shared/schemas.md`. Список апелляций
включает объединение окон по две реплики вокруг evidence_ids и концов
checked_range. Решение сохраняется транзакцией с изменением final и статуса
апелляции. Original остаётся неизменным; итог всегда рассчитывается из final.
Повторное решение и две одновременно открытые апелляции на один критерий
одной оценки отклоняются с HTTP 409.

`GET /api/stats` агрегирует только `llm_calls`. `tokens` — сумма входных и
выходных токенов, `avg_latency_ms` — средняя задержка вызова;
`avg_cost_per_eval` — суммарная стоимость / число уникальных evaluation_id
в журнале вызовов. Оценки полностью из кеша в этот знаменатель не входят.
При пустом журнале все значения равны нулю. Ошибочные попытки учитываются,
если ИИ вернул их метаданные в `error.calls`; сервер не выдумывает стоимость.

## Проверки

`npm test` покрывает расчёт 77.69 на общем моке, N/A, шкалы, грубую ошибку,
неизменяемость версий, импорт через HTTP, стабильность ID, очередь/повторы/
параллельность/кеш, восстановление SQLite после перезапуска, апелляции и расходы.
`node server/verify-start.js` отдельно запускает `npm start` с временной БД,
проверяет `/api/health` и останавливает сервер.
